# 错误选项的构造手法 —— 16 类

> 状态：active · 2026-09-02
> 来源：SAA-C03 全部 1019 道题富化过程中归纳，由富化会话逐轮提炼、主会话核实。
>
> **这份清单的价值不亚于逐题解析。** 逐题解析教你「这道题为什么选 B」，
> 这份清单教你「错误选项是怎么被造出来的」—— 后者可迁移到任何没见过的题。

---

## A 组 · 事实层面造假（选项描述的东西不存在）

### 1. 虚构的服务能力
给真实服务安上它没有的能力。

- Parameter Store「自动轮换」(#936) —— 那是 Secrets Manager 的能力
- Transit Gateway「提供加密」(#950) —— TGW 是托管路由器，不加密
- WAF 挂 Global Accelerator (#961)
- 只读副本「接收写流量」(#921) —— 只读副本不接受写入

### 2. 虚构的配置项
把 A 服务的配置项安到 B 服务上。

- RDS「按需容量模式」(#1002/#997) —— 那是 DynamoDB 的
- Aurora「Oracle 兼容版」(#978) —— Aurora 只兼容 MySQL/PostgreSQL
- ECS Anywhere 的「Fargate 启动类型」(#900)
- SSE-C「密钥存在 KMS 中」(#1009) —— SSE-C 的 C 就是 Customer-provided

### 3. 虚构的条件键/策略语义
造一个听起来合理但不存在的条件。

- 桶策略「拒绝非 Cognito 发起的请求」(#1011)
- 标签策略「拒绝运行实例」(#988) —— 标签策略只管标签合规，不能拒绝操作

### 4. 虚构的服务组合
**识别法：这两半真的能拼在一起吗？**

- Aurora + DAX (#864) —— DAX 是 DynamoDB 专属
- S3 桶作 NLB 目标
- 客户端加密配 S3 托管密钥
- Global Accelerator 以 S3 为端点 (#1015) —— GA 只支持 ALB/NLB/EC2/EIP

### 5. 量级/上限违规
数字直接越界，**可以当场算出来**。

- RDS 自动备份 90 天 > **35 天上限** (#978)
- 处理 20 分钟 > **Lambda 15 分钟上限** (#995/#1014)
- Glacier 深度归档 12h 取回用于**点播** (#995)
- 单个 Kinesis 分片 = 1000 records/s，题目要 10 万/s (#7)

## B 组 · 机制层面偷换（服务对，但对它怎么工作的描述是错的）

### 6. 描述与机制不符
- 「SQS 发送通知触发扩展」(#1001) —— SQS 是**拉取**模型，不推送
- 「为接口端点添加路由表条目」(#860) —— 那是**网关端点**的机制
- 「私有集成限制客户端 IP」(#1019)

### 7. 托管层级偷换（「托管」冒充「无服务器」）
- EKS **托管节点组**冒充「不管理底层基础设施」(#996) —— 节点还是你的

### 8. 侦测冒充预防
**检测性手段只通知人，不阻止事情发生。**

- Config 规则 + Lambda 删除，冒充 SCP 的**预防性**控制 (#988)
- ALB 健康检查冒充「主动移除实例」(#1006)
- 「配置低存储空间告警」冒充「自动扩容」(#276)

---

## C 组 · 维度错配（工具没问题，解决的不是题干问的那件事）

### 9. 正确工具用错维度
- 用 S3 访问点（**权限**维度）解决「不走公共端点」（**网络**维度，#998）
- 用数据库用户（**认证**）解决「公网暴露」（**网络**，#992）
- 用桶策略过滤 NAT 的 EIP 解决「不走互联网」(#1016)

### 10. 在非瓶颈层扩容/优化
- 数据库 CPU 打满却加 Web 实例 (#999)
- 处理层积压却给 Web 层加 CloudFront (#1012)
- 「用 NLB 替换 ALB 提升高可用」(#693/#639/#660) —— 换掉本来没问题的组件

### 11. 限流/降级冒充优化
- 「限制发往数据库的查询」冒充「提高性能」(#999 D) —— **少做一点 ≠ 做得更快**

---

## D 组 · 半对（最难排除的一类）

### 12. 只满足一半约束
双重约束题里只答对一半。**读题时先把约束逐条列出来。**

- #906「防丢失**且**不能无限期保留」—— IAM 禁止删除只满足前半
- #1003 存储卷解决了备份没解决容量（#1000 同型）

### 13. 一字之差的对调 ⭐ 最险
技术手段完全相同，只把两个对象**对调**。

- #1017：C 与 D 都是 IRSA，只把「UI→DynamoDB / 数据服务→S3」对调 ——
  胜负全在读题仔细程度

### 14. 孪生选项只差一个参数
**答案一定藏在那个唯一的差异里。**

- #920 B/D 逐字相同只差 REST vs **HTTP** API（后者便宜约 70%）
- #1000 缓存卷 vs 存储卷 · #987 ALB vs NLB · #950 VPN vs Transit Gateway
- #84 A≡C（译文缺陷导致，属于素材问题不是出题手法）

## E 组 · 反模式伪装

### 15. 自建已有托管服务的等价物
**「AWS 已经有这个服务了，为什么要自己搭？」**

- EC2 上装 NFS 服务器 (#986) —— 有 EFS
- 自建本地文件服务器 + S3 API (#1003) —— 有 Storage Gateway
- DynamoDB 上手工实现工作队列 (#991) —— 有 SQS
- Streams 重造全局表 (#1002) · Lambda 重造 SSM 运行手册 (#959) ·
  Batch 重造 S3 批量操作 (#912)

### 16. 破坏性动作伪装成方案
**这个操作本身会造成损失。**

- 「禁用 RDS 自动备份」会**立即删光现有自动备份** (#989)
- 「Lambda 自动删除不合规资源」(#988)
- 「停止实例改类型」在最繁忙时制造中断 (#1008)
- 用 Spot 跑数据库 (#997)

### 17. 过时技术信号
选项里出现已被取代的技术名词，通常是干扰项。

- 「把证书导入 IAM」(#823) —— ACM 之前的旧做法
- 「启动配置」(#677) —— 已被启动模板取代
- 「S3 随机前缀」(#690) —— 2018 年 S3 自动分区后不再需要
- 「AWS Data Pipeline」(#784) —— 已进维护状态

### 18. 绑定销售式构造
把一个**正确的能力**与一个**不必要的重大改动**捆在一起。

- #808 C =「迁到 EKS」（不必要）+「ECR 增强扫描」（正确）

> **拆解问法**：那个正确的能力**是否必须依赖那个改动**？
> （本例 ECR 扫描在 ECS 上完全可用，改动纯属多余）

## 配套读题技巧：反向指路牌

> 当某个选项**专门为题干里一个「看似无关的技术细节」辩护「这没问题」**时，
> 那个细节基本就是根因。

典型 #1006：题干特意写出「**IP 地址类型**的目标组」，而选项 B 说
「无需更改，因为它已针对 IP 地址类型目标组优化」—— **正因为它本来就不支持**。
题干的细节 + 一个替它辩护的选项 = 双重确认。
