# 学习流与页面架构

> 状态：active · 最后更新 2026-09-01
> 回答的问题：用户从进站到「知道自己哪里不会」的完整路径怎么走。
> 数据 schema 见 architecture.md；此处是页面信息架构 + 学习侧交互设计。

## 1. 页面信息架构（IA）

```
/                        未登录：宣言页（现状：34% 数据带 + 打架的题 + 题库目录）
                         登录后：学习概览 dashboard
                           · 「继续学习」卡（上次刷到的位置，一键回去）
                           · 总进度（做过/未做/正确率）
                           · 弱项 Top N（按标签正确率倒序）
                           · 各题库入口
/banks/[slug]            学习枢纽 —— 不再只是「开始刷题」一个按钮，而是模式菜单：
                           · 继续刷题（断点续刷）
                           · 顺序刷 / 只刷分歧题 / 只刷有解析的      ← 内容侧，已有
                           · 错题本 / 不清楚的 / 没做过的            ← 学习侧，需登录
                           · 按标签刷：考纲域 / 服务(S3、EC2…) / 概念  ← TagChip 点击即入，已有
/banks/[slug]/drill      刷题 runner。参数：mode + tag + i
/questions/[id]          单题详情（P4 在这里加「追问 AI」入口）
/me                      自我分析页：
                           · 做题进度（做过 / 未做 / 正确率）
                           · domain × service 正确率热图（「我哪里不会」）
                           · 错题列表 / 不清楚列表 / 问过 AI 的列表
/auth/login /auth/callback   Akasha OIDC
```

### drill 的 mode 参数（学习模式的统一表达）

```
mode=seq        顺序（默认）
mode=contested  只刷分歧题            ← 已实现（contested=true）
mode=enriched   只刷有解析的          ← 已实现（enriched=true）
mode=wrong      错题本                ← 需登录：attempt.correct=0 的题
mode=unsure     不清楚的              ← 需登录：自评为「模糊」的题
mode=unseen     没做过的              ← 需登录：无 attempt 记录的题
tag=N (可多个)  按标签，与 mode 可叠加
```

「上次刷到哪」：**从 attempt 推**（该模式下最近一次作答的位置），不新增断点表 ——
少一张要维护一致性的表，代价是切设备后断点按作答记录算，可接受。

## 2. 「记录学习行为」的数据模型增量

| 需求 | 落点 | 状态 |
|---|---|---|
| 做过 / 没做过 | `attempt` 有无记录（差集查询） | 表已建 |
| 做错的 | `attempt.correct = 0` | 表已建 |
| 不清楚的 | `attempt.rating`（自评，见下） | 字段已有，交互待定 ★决策点 2 |
| 问过 AI 的 | 新表 `ai_ask`（P4 建）：account_id, question_id, prompt, answer, created_at | 待 P4 |
| 学习进度分析 | `attempt ⋈ question_tag ⋈ tag` 聚合（architecture.md 已有查询） | 查询已设计 |

### 自评与 FSRS 的衔接 ★已定（2026-09-01）

`attempt.rating`（1-4）本来是 P3 FSRS 要的输入。**P2 就开始采集**，P3 上线时
历史作答直接可用，不用冷启动。

**采集方式：FSRS 标准四键** —— 每次揭晓后选 Again(1) / Hard(2) / Good(3) / Easy(4)。
决策理由：用户拍板，信号完整性优先于交互轻量（候选过「对错自动 + 二键自评」的
轻量方案，见下方留档）。

- 「不清楚的」集合 = rating ≤ 2 的题（Again + Hard）
- 答错但自评 Good 属于矛盾信号，UI 上不禁止（FSRS 语义里 rating 是回忆质量的
  主观陈述，客观对错由 `attempt.correct` 独立记录，两者并存不冲突）

## 3. 登录与版权边界 ★已定（2026-09-01）

**全站登录墙**（除登录页），凭 Akasha 账号进入 —— 用户拍板。

理由：这不只是产品选择，是版权风险控制。题库数据之所以放在私有仓（见 CLAUDE.md
「边界」），同一条理由同样适用于部署后的站点 —— 公网可访问且无登录墙 =
向任何人分发题库内容，代码仓再干净也没用。
个人学习工具 + 自研 IdP，登录成本近似为零，换来版权暴露面归零。

## 4. 实施顺序（P2 剩余）

```
1. Akasha OIDC 接入 + 登录墙       ← 一切个人化功能的前置
2. attempt 写入（对错 + 二键自评）
3. drill 增加 wrong / unsure / unseen 模式
4. 登录后首页 dashboard + /me 分析页
```

## 5. 被否决的方案（留档）

| 方案 | 否决理由 |
|---|---|
| 断点续刷单独建表 | attempt 可推导，少一张一致性要维护的表 |
| 对错自动记 + 答对二键自评 | 交互更轻，但信号比四键粗。用户拍板选标准四键，信号完整性优先 |
| 「不清楚」做成独立收藏按钮 | 收藏是主动行为、容易忘记按；自评挂在每次作答的必经路径上，数据才完整。收藏（星标）可作为后续补充，不冲突 |
